# SIGGRAPH Asia Teaser — Progress

## Project context

- **Submission**: SIGGRAPH Asia video.
- **Research project**: animal motion generation — take a **static animal mesh + text prompt**
  and produce a **dynamic animation** of that animal.
- **Teaser concept**: *Night at the Museum*. Animal models sit on a
  natural-history-museum exhibit pedestal in the dark hall; at some moment they
  "come alive" (this is where the motion-generation result enters).
- **Pipeline**: develop each shot as a three.js scene, preview in the browser,
  later render each scene to video, assemble shots in PowerPoint.

## Status

Stage 1 (scene_teaser) is **complete**. The shot is a slow rectangular pan
around a 6×15 grid of textured, animated animals sitting on a pedestal, with
a fixed museum backplate.

## Tech stack

- **three.js** `^0.169.0` (in `node_modules/three`)
- **Vite** `^5.4.10` dev server / bundler
- **No TypeScript**, no framework — plain ES modules.
- Addons used: `OrbitControls`, `GLTFLoader`, `AnimationMixer`.
- **Python 3.13** for offline GLB preprocessing (`pygltflib`, `Pillow`, `numpy`).

## Running on Windows

1. Install Node.js 20+ (Python 3.10+ for the preprocessor).
2. From the repo root:

   ```powershell
   npm install
   npm run dev
   ```

3. Open <http://127.0.0.1:5173/scene_teaser/>.

The dev server serves `/data/...` directly from `data/` (see `vite.config.js`
`server.fs.allow`).

### Regenerating manifests

`mesh/manifest.json` is generated, not source. Regenerate with:

```powershell
python -c "import os, json; d=r'data\all_animo_val\process1_textured_post2\mesh'; json.dump(sorted([f for f in os.listdir(d) if f.endswith('.glb')]), open(os.path.join(d,'manifest.json'),'w'))"
```

(swap the path for `post1` / any other dir if needed.)

### Dark-texture lift pipeline (post1 → post2)

A handful of GLBs ship with near-black albedo (e.g. wild water buffalo, siamang).
`data/scripts/lift_dark_textures.py` rewrites those into a parallel directory:

```powershell
python data\scripts\lift_dark_textures.py
```

It reads `process1_textured_post1/mesh/*.glb`, decodes each embedded texture,
and **only** lifts images whose mean luminance is below `DARK_THRESHOLD` (0.18).
Lifted images get autocontrast + gamma 0.6; everything else is copied through
byte-for-byte. Output goes to `process1_textured_post2/mesh/`. Currently
~9/90 GLBs are touched. After running, regenerate `manifest.json` for `post2`
and `MESH_BASE` in `scene_teaser/main.js` already points there.

## What scene_teaser does today

All in `scene_teaser/main.js`.

### Background
- 2D screen-space backplate (`scene.background = bgTexture`) using `museum.webp`.
- Custom "cover" aspect logic in `updateBackgroundAspect()`.
- No IBL.

### Lighting
- `ambient` white 0.55
- `keyLight` warm `0xfff1d8`, intensity 1.6, pos (2.5, 4.5, 2), casts shadows
- `fillLight` cool `0x99b4cc`, intensity 0.55, opposite side
- `rimLight` 0.3 backlight from behind
- Animals also get `emissiveMap = baseColorMap` at `emissiveIntensity = 0.15`
  (texture-driven self-illumination — keeps the museum mood while lifting
  very dark fur out of the shadows without washing out bright animals).

### Pedestal
- `PEDESTAL = { w: 10.0, h: 0.85, d: 5.1 }` — long, low platform.
- Off-white `MeshStandardMaterial` (`#eae5dc`), casts + receives shadows.
- Wrapped in `displayGroup` (a plain `THREE.Group`) so the entire pedestal +
  animals tour together (camera stays fixed).

### Animal grid
- **6 rows × 15 cols = 90 cells.** `PAD = 0.4` m inset on each pedestal edge,
  so the grid lives in a 9.2 × 4.3 m area.
- Cell size: 0.613 × 0.717 m.
- `ANIMAL_SCALE = 0.4` — uniform multiplier on every model. We deliberately
  **do not** bbox-normalize per animal: post1 already volume-normalizes them
  (reference volume 0.066 m³), so a global scale preserves the modest
  size differences post1 left in (elephant slightly bigger than aardvark).
- `ANIMAL_LIFT = 0.002` — 2 mm offset above pedestal to avoid z-fighting.
- Animations **play** (one mixer per GLB). See "Frame-0 grounding" below.
- Loading is bounded-concurrency `LOAD_CONCURRENCY = 8`.

### Per-animal tweaks
- `ROTATE_180` set: ~38 GLBs whose authored facing direction is wrong.
  Rotation happens before bbox / centering math runs. Indexed by full
  manifest filename (positions in the 6×15 layout — if the layout changes,
  the list needs to be regenerated).
- `SCALE_OVERRIDES` map: currently empty. Substring-matched on lowercase
  filename. Multiplies on top of `ANIMAL_SCALE`. (Used briefly to scale up
  the alligator before we removed the bbox normalization; not needed now.)

### Frame-0 grounding (important)
The textured GLBs encode their "animated" position via root translation +
morph targets: frames 1+ have a morph that pulls the deformed mesh back to
origin-on-floor, but frame 0 has no morph and the static rest pose sits at
a different world position. Naively computing the bbox without animation
gives the wrong center, and the model snaps out of its grid cell the instant
animation starts.

Fix (in `placeAnimal`):
1. Create the `AnimationMixer`, play the clip, then `mixer.update(0)` to
   evaluate frame 0 **before** any bbox math.
2. For y-grounding, sample 30 evenly-spaced times across the clip and take
   the minimum bbox.min.y across the sweep — so a crouching / stomping
   frame doesn't sink the feet into the pedestal.
3. **Both** `Box3.setFromObject` calls pass `precise = true`. Without that,
   three.js reads `geometry.boundingBox` (static, ignores morph targets) and
   all sampled frames return the same bbox.
4. xz centering stays on frame 0 (animation horizontal drift is small;
   averaging didn't help and was slower).

### Camera
- `PerspectiveCamera`, FOV **5.0°** (tight telephoto — frames roughly 3 rows
  × ~6 cols of the grid at a time).
- `camera.position = (0, 8.0, 11.5)`, `controls.target = (0, 0.9, 0)`.
  Look-down angle ≈ 35°.
- `OrbitControls` enabled for dev preview. **Disable / lock for final renders.**

### Tour animation
- Camera is **fixed**. `displayGroup` walks a rectangle so different chunks
  of the grid drift across the framed viewport. Four corners:

  ```
                cols 0–5         cols 9–14
   rows 0–2     A ─── 缓慢向右 ──▶ B
                ▲                  │
                │                  │ 往下
           最后往上                  ▼
                │                  │
   rows 3–5     D ◀── 然后往左 ─── C
  ```

- Order: `A → B → C → D → A`. Loops forever.
- `tour.xAmp = 3.4`, `tour.zAmp = 1.075`, `tour.period = 30.0` s.
- **Linear interpolation, constant speed** — time per segment is proportional
  to its distance, so velocity stays uniform around the rectangle (no
  slowdown at corners). `tourPos(t)` in `main.js`.

### Render settings
- ACES Filmic tone mapping, sRGB output.
- PCF soft shadow map at 2048×2048 on `keyLight`.
- DPR clamped to 2 (`Math.min(window.devicePixelRatio, 2)`).

### Dev handle
`window.__scene` exposes
`{ scene, camera, controls, renderer, pedestal, displayAnchor, keyLight,
fillLight, rimLight, ambient, animalsRoot, displayGroup, tour }` — tweak from
DevTools while iterating (e.g. `__scene.tour.period = 45` or
`__scene.tour.enabled = false`).

## Known issues / sharp edges

- **Load time**: 90 GLBs × 30 precise-bbox samples each ≈ several seconds on
  the loading screen (precise=true iterates every vertex). Acceptable for
  preview, but if it gets worse, halve `samples` or drop precise on the
  centering bbox.
- **xz drift during animation**: we only center on frame 0 xz. Most morph
  animations are small-amplitude so this is invisible, but if a future
  animation pack has larger horizontal motion, switch to a sequence-average
  xz like we did for y.
- **Background is screen-locked**: fine for the mostly-static teaser, but
  if we ever add camera motion within a single shot, the backplate will feel
  glued. Switch to a real 3D backplate plane or HDRI.
- **Hard-coded grid layout in `ROTATE_180`**: it's a filename list derived
  from positions in the 6×15 manifest. Regenerate the list if grid size or
  manifest ordering changes (see helper PowerShell snippet in chat history).

- **"Coming alive" beat**: where the motion-generation result enters. Options:
  one animal stepping forward while others stay frozen, a wave across rows,
